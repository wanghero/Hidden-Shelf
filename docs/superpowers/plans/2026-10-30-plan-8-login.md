# Hidden Shelf 计划 8：在浏览器里登录来源站 Implementation Plan

> **For agentic workers:** 本计划由本机会话直接实现（用户 2026-10-30 定：不再交云端）。Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户要的原话：「avbase 冷却中、javdb 要登录 或者其他的数据库，需要登录的，写程序（含开关），让我登录」。要登录或要过验证的来源站，不再让用户手抄 Cookie 请求头：程序弹出一个真浏览器窗口，用户在里面登录（或过 Cloudflare 验证），程序把该站 Cookie 与浏览器 User-Agent 存进 `~/.hidden-shelf/config.json`，之后刮削带着它们去请求。每站有开关，冷却能一键清。

**Architecture:** 登录流程是一个纯函数式的核心 `scrape/login.py::capture_login(source, …, launch=)`：`launch(url)` 回一个「浏览器句柄」（能列 Cookie、取 UA、判断是否已关、关闭），默认实现用 Playwright 的有头 Chromium，测试传假句柄。流程每半秒抓一次该站域名下的 Cookie 快照，用户关掉窗口或按「完成」就用最后一份快照落盘。命令行 `shelf login <站>` 与进度网页 `POST /api/login` 都调它；网页另有 `GET/POST /api/sources`（列表、开关）与 `POST /api/cooldown/clear`。传输层改成「配置里有这一站的 Cookie 就带，有 UA 就用那个 UA」，不再只认登记了 `cookie: True` 的站（avbase 的 Cloudflare 放行 Cookie `cf_clearance` 绑 UA，所以 UA 必须一起存）。

**Tech Stack:** 现有 + 可选依赖 `playwright`（`uv sync --extra login` 后 `uv run playwright install chromium`）。没装时命令行与网页都给出这两条命令，不崩。

**Spec:** 设计文档 §4.5（全局配置与凭据：凭据只住 `~/.hidden-shelf/config.json`）。本计划不改这条：Cookie 与 UA 仍只进全局配置，日志与网页只说「有/无」。

## Global Constraints

- 版本接着 `main` 当前的 **0.4.14**：Task 1 → 0.4.15，Task 2 → 0.4.16。三处同改，提交信息中文，提交后 push。
- 凭据不进日志、不进 SSE 事件、不进 `/api/sources` 响应（只给布尔）。
- 进度网页仍只监听 127.0.0.1；登录窗口在跑 `shelf serve` 的那台机器上弹出。
- 前端沿用 `ux-standard`：只用 token，中英字典同键。

## Review Focus

1. **没装 Playwright**：`shelf login javdb` 退出码 2，打印两条安装命令；网页「登录」按钮回 400 带同样文案。→ `test_login_unavailable_message`。
2. **用户直接关窗口**：最后一份 Cookie 快照仍落盘，不因为窗口没了就空手而归。→ `test_capture_uses_last_snapshot_when_window_closes`。
3. **一个 Cookie 都没拿到**（用户没登录就关了）：不覆盖原有 Cookie，报「没有拿到 Cookie」。→ `test_capture_without_cookies_keeps_old_value`。
4. **UA 随 Cookie 一起用**：有 UA 的站请求头用它，没有的用默认串；Cookie 只发给该站域名。→ `test_source_transport_uses_saved_user_agent`。
5. **开关**：`POST /api/sources {name, enabled:false}` 后 `GlobalConfig.enabled` 为假，刮削链跳过它。→ `test_sources_toggle_persists`。

### Task 1: 登录流程核心、传输层带 UA、命令行 `shelf login`（0.4.15）

**Files:**
- Modify: `src/hidden_shelf/netconfig.py`（`SourceSettings.user_agent`、`describe` 加 `user_agent: bool`、`set_login(source, cookie, user_agent)`）
- Modify: `src/hidden_shelf/scrape/access.py`（`SOURCES[*]["login_url"]`；`_transport_for` 带 Cookie 与 UA 的条件）
- Create: `src/hidden_shelf/scrape/login.py`
- Modify: `src/hidden_shelf/cli.py`（`login` 子命令）
- Modify: `pyproject.toml`（`[project.optional-dependencies] login = ["playwright>=1.47"]`）
- Test: `tests/test_login.py`、`tests/test_access.py`、`tests/test_netconfig.py`

**Interfaces:**
- `login.LOGIN_SOURCES: tuple[str, ...]` 要登录或要过验证的站（javdb、javbus、avbase）。
- `login.availability() -> str`：空串表示 Playwright 可用；否则是给用户看的安装说明。
- `login.capture_login(source: str, *, config: GlobalConfig, finish: threading.Event, notify=print, launch=launch_browser, poll_seconds=0.5, timeout=600) -> LoginResult(cookies: int, user_agent: str)`；抛 `LoginError`（给人看的消息）。
- `launch(url) -> BrowserHandle`，句柄协议：`cookies() -> list[dict]`（Playwright 原样：`name/value/domain`）、`user_agent() -> str`、`closed() -> bool`、`close()`。
- `GlobalConfig.set_login(source, cookie: str, user_agent: str) -> None`（写内存，调用方 `save()`）。

- [ ] Step 1: 测试 `tests/test_login.py`（假句柄：预置几轮快照、`closed` 在第 N 轮变真）、`test_access.py::test_source_transport_uses_saved_user_agent`、`test_netconfig.py` 的 UA 往返。
- [ ] Step 2: 实现。`login.launch_browser` 用 `playwright.sync_api`，`headless=False`，`context.cookies()` 取全部再按域名筛；可执行文件缺失的错误映射成「`uv run playwright install chromium`」。
- [ ] Step 3: `shelf login <站>`：打印「浏览器已打开，请登录；登录完成后关掉窗口，或回这里按回车」；后台线程读 stdin 一行置 `finish`。成功打印「已保存 N 个 Cookie，UA 已记录」。
- [ ] Step 4: 全量测试，版本 0.4.15，提交。

- Modify: `src/hidden_shelf/serve/static/progress.js`、`i18n.js`、`progress.css`
- Test: `tests/test_serve_app.py`、`tests/test_serve_sources.py`

**Interfaces:**
- `GET /api/sources?root=` → `{sources: [{name, label, enabled, needs_login, cookie, user_agent, cooldown_until (ISO|null), login: {status: idle|running|done|failed, message}}], login_available: bool, login_hint: str}`。
